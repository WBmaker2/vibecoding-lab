# HVC UI/UX 전환 구현 계획

작성일: 2026-09-07
상태: 구현 완료 · 배포 전

## 목표

114개 이상의 교육용 웹앱을 교사가 빠르게 찾고, 관리자가 안전하게 정리·수정할 수 있도록 기존 Next.js 앱을 단계적으로 개선합니다. 공개 앱 주소, 정적 갤러리 스냅샷, DB/공개 반영 분리 계약은 유지합니다. 로그인 없이도 기기별 보관함과 큐레이션 모음을 제공해 반복 탐색 비용을 줄입니다.

## 적용 순서

1. 데이터 분류 안정화: 과목 별칭·학년군 정규화, 검색 동의어 기반 마련.
2. 검색 핵심 개선: 공백 단어 검색, 제목 우선순위, 과목·학년군·대상·활동 방식 필터, 정렬·페이지·URL 복원.
3. 공개 랜딩 개선: 축약된 히어로, 필터 패널, 결과 정렬·페이지, 간결한 카드, 상세에서 목록 조건 복귀.
4. 관리자 운영 개선: 목록 검색·필터·페이지, 목록과 편집 패널 연결, 미저장 보호, 앱 삭제 확인, 태그 검색·점진 표시, 반영 상태 요약.
5. 반응형·접근성 개선: 320/375/768/1440px, 가로 넘침 제거, 고정 저장 바, focus-visible, reduced-motion, 44px 목표 영역.
6. 반복 사용 지원: 빠른 수업 모음, 기기 내 보관함·최근 사용 기록, 목록 URL, 관리자 선택 앱의 일괄 태그·분류 변경.
7. 마감 검수: 자동 테스트·lint·build와 브라우저 공개/관리자 흐름을 분리하여 확인하고 결과를 기록합니다.

## 변경 후보

- `src/lib/apps/metadata.ts`: 분류 표준명·별칭과 `중학생` 학년군 정규화.
- `src/lib/search/filter-apps.ts`: 토큰 검색·검색 점수·구조화 필터.
- `src/features/archive/*`: 필터 모델, URL 상태, 정렬·페이지, 모바일 필터, 카드 요약, 수업 모음·기기 내 보관함·최근 사용.
- `src/features/app-detail/*`: 목록 검색 조건 보존 링크.
- `src/features/admin/*`: 목록 컨트롤, 편집 패널/초안 보호, 태그 점진 표시, 선택 앱 일괄 태그·분류 작업.
- `src/app/globals.css`: 레이아웃 토큰, 모바일 폭, 저장 바·상태 스타일.
- `src/data/public-apps.json`: 직접 생성 스냅샷은 일괄 수정하지 않고 런타임 정규화로 기존 ID·URL을 보존합니다.
- `docs/2026-09-07-hvc-ui-ux-analysis.md`: 구현 후 실제 변경·검증 결과 보완.

## 수용 기준

- `과학 5학년`, `5학년 과학`처럼 단어 순서가 다른 검색이 같은 의도에 대응합니다.
- 과목·학년군·대상·활동 방식의 조합 결과와 선택 조건을 확인할 수 있고, URL을 새로 열어도 복원됩니다.
- 114개 목록은 페이지 단위로 탐색하며 결과 수와 정렬 상태를 볼 수 있습니다.
- 빠른 수업 모음은 교과·학년군·대상·활동 방식 필터로 전환되고, 카드 저장·앱 실행 기록은 같은 기기에서 보관함·최근 사용 목록으로 다시 열 수 있으며 전체 비우기를 확인합니다.
- 상세에서 목록으로 돌아올 때 검색·필터·정렬·페이지가 유지됩니다.
- 관리자 목록에서 특정 앱을 검색하여 편집하고, 편집 버튼 선택 후 수정 영역을 바로 볼 수 있습니다.
- 저장하지 않은 변경을 앱 전환·신규 등록 전환·페이지 이탈로 잃지 않으며, 폐기 선택은 명시적으로 수행합니다.
- 앱 삭제는 대상 앱과 결과를 확인한 뒤에만 제출됩니다.
- 관리자에서 여러 앱을 선택해 태그와 분류를 일괄 변경할 수 있고, 마지막 태그를 지우는 요청은 변경 전에 차단됩니다.
- 375px에서 `document.documentElement.scrollWidth`가 viewport를 초과하지 않고, 폼 저장이 고정 또는 쉽게 찾을 수 있는 위치에 있습니다.
- 기존 공개 반영 API, 백업, 인증, 정적 스냅샷 흐름이 깨지지 않습니다.
- VoiceOver는 구현·검증 범위에서 제외합니다.

## 위험과 완화

- 메타데이터를 원본 JSON에 직접 덮어쓰면 정적 반영과 DB가 어긋날 수 있으므로 정규화 계층을 우선 사용합니다.
- URL 상태가 검색엔진 색인을 과도하게 만들 수 있으므로 필터 UI는 client state와 query string을 제한적으로 동기화하고 canonical 정책을 유지합니다.
- 관리자 목록에서 서버 액션을 반복 호출하지 않도록 편집 선택은 로컬 상태, 저장·삭제만 기존 액션을 사용합니다.
- 동기화 상태는 실제 배포 확인과 분리된 상태로 표시합니다. 성공 실행을 공개 확인 완료로 과장하지 않습니다.
- 새 의존성은 추가하지 않습니다.

## 검증 명령

```text
npm test
npm run lint
npm run build
npm run test:e2e
```

브라우저 검수는 ego-browser로 공개 홈의 검색·필터·상세 복귀, 관리자 로그인·목록 검색·편집·미저장 보호를 확인합니다. 저장·삭제·동기화·백업은 테스트용 변경 없이는 실행하지 않습니다.

## 롤백

기능 단위 커밋 없이 작업하는 동안에도 변경 파일을 단계별로 확인합니다. 문제 발생 시 해당 단계의 파일만 기존 내용으로 되돌리고, 생성한 계획·검수 문서는 보존합니다. 기존 데이터 스냅샷과 이미지 원본은 삭제하거나 덮어쓰지 않습니다.
